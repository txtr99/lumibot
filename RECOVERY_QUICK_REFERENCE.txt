CRITICAL RISKS (Must Fix Before Production)
================================================================================

1. INFINITE LOOP RISK
   What: Close order fails, but virtual marked flat anyway
   Where: flatten_symbol() in tools/order_registry.py
   Impact: Next sync check triggers flatten AGAIN → loop
   Fix: Confirm close order BEFORE marking virtual flat

2. BRACKET DUPLICATION
   What: brackets_submitted flag resets to False on restart
   Where: EnhancedStrategyState.__init__() in multi_strategy_executor_enhanced.py
   Impact: Resubmits SL/TP orders → 2 TP + 2 SL on exchange
   Fix: Persist brackets_submitted flag to disk

3. NO STATE PERSISTENCE
   What: All state is in-memory, lost on crash
   Where: VirtualPositionTracker, OrderRegistry, BracketOrderManager
   Impact: Restart sees empty state → auto-flattens everything
   Fix: Add save_state() and load_state() methods

4. ORPHANED ORDERS
   What: Orders from previous session still OPEN when market opens
   Where: No cleanup logic in run_portfolio.py on startup
   Impact: Old order fills unexpectedly → creates mismatch
   Fix: Query orders on startup, flag/cancel stale ones

5. RACE CONDITION IN FLATTEN
   What: Virtual position marked flat BEFORE close order confirms
   Where: flatten_symbol() line 492-500 in tools/order_registry.py
   Impact: If close fails, next iteration triggers infinite loop
   Fix: Move tracker.close_position() to AFTER close confirms

EMERGENCY RESPONSE
================================================================================

If Bot Crashes During Live Trading:

1. STOP THE BOT IMMEDIATELY
   - Kill process: pkill -f run_portfolio.py
   - Verify no pending orders on exchange
   - Check current positions manually

2. CHECK STATE FILES
   - Do state files exist? (/lumibot_state/)
   - Are they valid JSON?
   - How old are they?
   - Can you restore from backup?

3. DIAGNOSE MISMATCH
   - Query exchange for current positions
   - Query OrderRegistry for pending orders
   - Compare with state files
   - Look for discrepancies

4. DECIDE NEXT ACTION
   - If virtual == exchange: Safe to restart
   - If virtual != exchange: Need manual reconciliation
   - If brackets orphaned: Need to clean up manually
   - If orders stale: Need to cancel before trading

5. RESTART CAREFULLY
   - Restart bot
   - If sync mismatch detected, check logs
   - Verify flatten executed correctly
   - Resume trading only after recovery complete

DO NOT:
  - Restart bot without checking state
  - Ignore sync mismatch warnings
  - Trade while positions are ambiguous
  - Assume exchange is always correct (could be stale)
