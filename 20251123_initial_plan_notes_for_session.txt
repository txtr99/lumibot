     │                                                                                                                                                                                     │
     │ 1. Timezone Strategy                                                                                                                                                                │
     │                                                                                                                                                                                     │
     │ - Internal Calculations: Central Time (America/Chicago) - ALL session times, platform rules, calendar logic                                                                         │
     │ - User-Facing: Mountain Time (America/Denver) - Display, logs, configuration input                                                                                                  │
     │ - Conversion Layer: Explicit CT↔MT conversion at display/input boundaries only                                                                                                      │
     │ - DST Handling: UTC→CT conversions MUST check DST status; CT↔MT conversions safe (same DST schedule)                                                                                │
     │                                                                                                                                                                                     │
     │ 2. Backtest Enforcement                                                                                                                                                             │
     │                                                                                                                                                                                     │
     │ - Default: ENFORCE_SESSIONS_IN_BACKTEST=true - Sessions enforced by default for realistic results                                                                                   │
     │ - Override: Can disable for signal exploration, but must explicitly opt out                                                                                                         │
     │                                                                                                                                                                                     │
     │ 3. Failure Mode (Live Trading)                                                                                                                                                      │
     │                                                                                                                                                                                     │
     │ - Calendar Creation Failure: Hard fail - abort startup completely                                                                                                                   │
     │ - Rationale: Never violate TopStepX rules; better to not trade than trade incorrectly                                                                                               │
     │ - Emergency Override: Manual env var CALENDAR_EMERGENCY_DISABLE=true for critical situations                                                                                        │
