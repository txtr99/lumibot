CRITICAL FINDINGS (Must Fix Before Production)
================================================================================

1. NO PERSISTENCE LAYER FOR STATE
   - VirtualPositionTracker: entirely in-memory, lost on crash
   - OrderRegistry: entirely in-memory, lost on crash
   - BracketOrderManager: entirely in-memory, lost on crash
   - Impact: Restart always sees empty registry, can't detect orphaned orders
   - Risk Level: CRITICAL

2. INFINITE LOOP RISK IN NUCLEAR FLATTEN
   - Close order fails but virtual position marked flat anyway
   - Next sync check: virtual=0, exchange=5 (close didn't execute)
   - Triggers FLATTEN_SYMBOL again
   - Recursive retry loop possible
   - Risk Level: CRITICAL

3. BRACKET SUBMISSION WILL DUPLICATE ON RESTART
   - state.brackets_submitted flag is reset to False on new instance
   - Bot will resubmit SL/TP orders even though originals still exist
   - Results in 2 TP orders, 2 SL orders on exchange
   - Risk Level: CRITICAL

4. REGISTRY LOSS PREVENTS DUPLICATE ORDER DETECTION
   - has_pending_close() returns False after restart (registry empty)
   - Bot proceeds to submit new entry order
   - Two entry orders on exchange for same strategy
   - Risk Level: CRITICAL

5. ORPHANED ORDERS FROM PREVIOUS SESSION NOT CLEANED UP
   - Order created 15:55, session close 16:00
   - Bot doesn't restart until next day
   - Old order still OPEN on exchange
   - Could fill unexpectedly when market opens
   - Risk Level: HIGH

CODE VULNERABILITIES IDENTIFIED
================================================================================

VirtualPositionTracker (lumibot/tools/virtual_position_tracker.py)
  - Missing: Serialization methods (save_state, load_state)
  - Missing: Checksum validation
  - Missing: Backup/rotation pattern

OrderRegistry (tools/order_registry.py)
  - Missing: Persistence layer
  - Issue: has_pending_close() returns False when registry lost
  - Issue: check_position_sync() only validates position qty, not order state
  - Issue: flatten_symbol() marks position flat BEFORE close confirms

BracketOrderManager (tools/bracket_order_manager.py)
  - Missing: Persistence layer
  - Missing: Orphaned order detection
  - Missing: Session boundary cleanup

MultiStrategyExecutorEnhanced (custom_portfolio/multi_strategy_executor_enhanced.py)
  - Issue: EnhancedStrategyState.brackets_submitted reset on restart
  - Missing: State persistence across restarts
  - Issue: No archaeology for pending brackets

RunPortfolio (custom_portfolio/strategies/run_portfolio.py)
  - Missing: Cold start detection (exchange positions + empty local state)
  - Missing: Old order cleanup on startup
  - Missing: State recovery prompt before proceeding
