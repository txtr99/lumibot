<workflow>
<step_1>
**Parse EasyLanguage file structure**:
- Header section: Extract symbol, profit/stop multiples, max time
- Inputs section: Extract parameters (atr_length, pt_mult, sl_mult, Max_Time, etc.)
- Entry section: Identify condition1 logic for long entries (Buy commands)
- Entry section: Check for short entries (SellShort commands)
- Exit section: Note any custom exit logic (usually standardized)
</step_1>

<step_1b>
**Detect source type and identify SQ_ functions**:

Check if file is from Strategy Quant X:
- Header contains "Generated by StrategyQuant X" → SQX export
- Any function call contains `SQ_` anywhere in name → SQX functions present

**If SQX functions detected, MANDATORY workflow**:
1. Extract ALL function names containing `SQ_` from the entry logic
2. For EACH `SQ_` function, look up its implementation:
   ```
   /Users/marvin/repos/lumibot_fork/custom_portfolio/strategies/templates/SQX_EasyLanguageFunc/f_SQ_<FunctionName>.elf
   ```
3. Read the `.elf` file to understand:
   - All input parameters and their meanings
   - Switch/case logic for multi-output functions (e.g., `Line` parameter)
   - Any nested `SQ_` function calls that also need lookup
4. Document what each parameter does BEFORE converting to Python

**NEVER GUESS SQ_ FUNCTION BEHAVIOR**:
- `SQ_MACD(..., 0)` vs `SQ_MACD(..., 1)` returns DIFFERENT outputs (main vs signal line)
- `SQ_IndicatorCrossesBelowMA(..., 3)` uses WMA, not SMA (MAType: 1=SMA, 2=EMA, 3=WMA, 4=Hull)
- These distinctions are IMPOSSIBLE to infer without reading the source

**Example - Correct lookup workflow**:
```
LongEntrySignal = SQ_IndicatorCrossesBelowMA(SQ_MACD(MedianPrice, 16, 37, 10, 0)[1], 49, 3)[1];

Step 1: Identify SQ_ functions: SQ_IndicatorCrossesBelowMA, SQ_MACD
Step 2: Read f_SQ_MACD.elf → Line=0 means MACD main line (not signal)
Step 3: Read f_SQ_IndicatorCrossesBelowMA.elf → MAType=3 means Weighted MA
Step 4: Now implement knowing: "MACD main line crosses below 49-period WMA"
```

See [references/sqx-functions.md](references/sqx-functions.md) for common SQX patterns.
</step_1b>

<step_3>
**Convert entry conditions to Python - COMPLETE IMPLEMENTATION REQUIRED**:
Parse condition1 logic and convert EVERY component into working Python code.

**CRITICAL**: You MUST fully implement ALL indicators and conditions. NO TODO comments, NO placeholders, NO incomplete code. The generated strategy must be runnable and generate signals immediately.

**EasyLanguage patterns → Python equivalents**:
- `average(close, 20)` → `closes.rolling(20).mean()`
- `xaverage(close, 20)` → `closes.ewm(span=20).mean()`
- `rsi(c, 14)` → `ta.rsi(closes, length=14)` (pandas-ta)
- `ADX(20)` → `ta.adx(df, length=20)['ADX']` (pandas-ta)
- `macd(c, 12, 26, 9)` / `macdhist(...)` → `ta.macd(closes, fast=12, slow=26, signal=9)`
- `KaufmanEfficiencyRatio(10)` → custom implementation (see indicator-mappings.md)
- `crosses above/below` → compare current vs previous (full pattern in indicator-mappings.md)
- `[0]` → `.iloc[-1]` (most recent bar)
- `[1], [2], [N]` → `.iloc[-1-N]` (N bars ago)

**Example - COMPLETE conversion (NOT acceptable to leave as TODO)**:
```python
# EasyLanguage: low[0] > xaverage(close,100) and rsi(c,2)[0] >= 80 and macdhist(c,12,26,9)[0] <= macdhist(c,12,26,9)[1]

# Python - FULLY IMPLEMENTED:
def populate_indicators(df, params):
    closes = df["close"]
    lows = df["low"]

    ema_100 = closes.ewm(span=100).mean()
    rsi_2 = ta.rsi(closes, length=2)
    macd_data = ta.macd(closes, fast=12, slow=26, signal=9)
    macd_hist = macd_data['MACDh']

    return {
        "ema_100": ema_100.iloc[-1],
        "low": lows.iloc[-1],
        "rsi_2": rsi_2.iloc[-1],
        "macd_hist_current": macd_hist.iloc[-1],
        "macd_hist_prev": macd_hist.iloc[-2],
    }

def go_long(state, df):
    indicators = populate_indicators(df, state.params)

    condition = (
        indicators["low"] > indicators["ema_100"] and
        indicators["rsi_2"] >= 80 and indicators["rsi_2"] <= 90 and
        indicators["macd_hist_current"] <= indicators["macd_hist_prev"]
    )

    return condition
```

EasyLanguage often has date/time filters: `Date[0] > 1250202 or (Date[0]=1250202 and Time[0]>=1800)`
- **Ignore these** in Python conversion
- Template framework handles date filtering via backtest parameters
- Focus only on technical indicator logic
</date_time_filters>

<crosses_and_comparisons>
EasyLanguage: `crosses above`, `crosses below`
Python equivalent:
```python
# crosses above: was below, now above
previous_below = indicator1.iloc[-2] <= indicator2.iloc[-2]
current_above = indicator1.iloc[-1] > indicator2.iloc[-1]
crosses_above = previous_below and current_above
```
</crosses_and_comparisons>
